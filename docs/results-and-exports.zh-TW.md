# 閱讀與分享檢查結果

[English](results-and-exports.md) · [使用說明](README.zh-TW.md)

掃描結束或停止後，打開**掃描結果**。先看摘要：哪些系統或檔案需要注意、哪個問題該先處理，以及下一步可以怎麼做。掃描還在進行時，請在**掃描進度**查看。

已入案的原始碼稽核會顯示在**掃描結果**，包含已確認問題、獨立的**待驗證**清單、尚未完成的單元與繼續路徑，以及可展開的方法、證據與來源詳細資料。候選問題不計入問題數。桌面版提供單輪 HTML、JSON、整合報告、框架報告、OCSF、OSCAL 與已簽署案件包；單輪與整合 HTML 可附上原始碼稽核原件。

## 看懂每一種結果

| 報告顯示的結果 | 代表什麼 |
| --- | --- |
| 發現問題 | 安全檢查找到至少一個影響這個項目的問題。打開後可以查看證據與建議做法。 |
| 已完成的檢查沒有發現問題 | 完成的檢查在本次範圍內沒有找到問題，不代表所有風險都已排除。 |
| 未完成或失敗 | 有些檢查沒有完成，其他已完成的結果仍然保留。 |
| 未測試 | 這個項目還沒有完成任何適用的安全檢查。 |

報告也可能列出服務、開放的連接埠或已安裝的軟體，幫你了解系統現況。這些是盤點資料，不會算成漏洞。

## 決定先處理什麼

先看排在前面的重要問題。每一項都會說明影響對象、為什麼值得注意，以及可以先做什麼。有適用資訊時，也會提供確認修正是否有效、或還原變更的方法。

要交給其他人調查時，可以展開技術細節。裡面保留原始掃描工具、規則編號、證據、嚴重程度與修正建議。「未知」表示工具沒有提供嚴重程度評級，不代表問題不重要。

程式會提供建議，不會自行修改你的系統。

## 確認還有哪些沒查到

查看**實際測試的內容**與**未測試的內容**。即使部分工作沒完成，報告裡的其他發現仍然有用。連線成功，或列出了系統清單，都不等於做過安全檢查。

尚未完成的檢查，請依照程式顯示的下一步處理。有些項目需要重新登入，或補齊資料，才能繼續。

## 之後回來看，也能比較前後結果

從**我的掃描**開啟專案，就能找到原本的目標、問題、證據與報告紀錄。閱讀或匯出前，先選好要看的那一次掃描。

兩次掃描可以比較時，程式會列出新增、仍存在與已解決的問題。無法比較的項目會另外標示，避免把「這次沒查到」誤認成「已經修好了」。

## 存一份報告分享

在**掃描結果**按**保存或分享報告**，選擇 **HTML 報告（建議）**。除非收件人需要辨識系統名稱等資訊，否則保留遮蔽敏感資訊的設定。儲存後，用瀏覽器開啟檢查，再決定是否分享。

報告會使用程式目前的語言，支援英文與繁體中文，閱讀順序也和畫面相同。技術證據可以展開查看，正式條款放在最後。儲存報告只會建立本機檔案，不會替你寄送給任何人。

要把原始報告保存在同一份 HTML，請關閉**遮罩敏感識別資訊**，再勾選**在報告最後附上原始報告**。最後的附件區會按每項掃描工具工作提供 ZIP。下載並完整解壓縮後，就能開啟原始報告，以及所需的圖片和其他配套檔案。沒有產生 HTML 的工具可能只提供 JSON、XML 或紀錄；未完成的檢查仍保留原本狀態。原始檔可能含敏感資訊。

分享附件時請保留 HTML；列印或另存成 PDF 不會帶出附件。HTML 最多附上 64 MiB 或 10,000 個原始檔，較大的資料集合請使用技術案件包。

## 開發版的報告保存與案件還原

尚未發布的新核心加入[完成掃描／匯出時的自動報告快照與離線取回／重播](report-snapshots.md)、合併原始附件下載，以及[私密案件封存／還原](case-archives.md)。還原保留既有案件資料，不會恢復掃描授權。原始附件與私密封存須依文件明確選擇包含敏感資料。

[Cloudflare 保存資料](cloudflare-provider.md)可離線檢查並取回，已入案稽核可使用下列共用報告，但完整案件封存仍未接入；資料包通過驗證或原件已保存，不代表稽核已執行。選用開發指令前，請看[發布定義與可用範圍](release-model.zh-TW.md)。

## 開發版的已入案原始碼稽核

已入案的 [Cloudflare 原始碼稽核](cloudflare-provider.md#admitting-a-sealed-audit)可出現在單輪與合併 HTML／JSON 報告及報告快照。已確認問題保留於資產表和優先清單，敘述依所選遮蔽設定呈現。**待驗證**線索沒有嚴重程度，也不計入漏洞；**未測試項目**列出未涵蓋單元、狀態與後續路徑。稽核未完成時仍保留已確認問題。第一層的方法名稱為「Cloudflare 原始碼稽核」；每項稽核的剩餘單元彙整為一列缺口且不重複增加未測試計數，範圍外單元另彙整為一列排除項目。剩餘單元共用一項下一步：「請從列出的路徑繼續原始碼稽核。」標準遮蔽保留此產品句子；後續路徑仍列於**未測試項目**及技術詳細資料，在標準設定下使用位置標記。英文與繁體中文只翻譯產品標籤，不翻譯供應者文字。展開技術詳細資料可查看方法、已發出的呼叫次數、角色與狀態計數、嘗試紀錄、來源沿革及原件摘要。

標準遮蔽對提供者敘述、追蹤與證據說明、修復策略、涵蓋紀錄文字及未完成原因套用共用遮蔽政策，分別計算隱藏的文字與程式碼欄位。檔案、路徑、來源範圍與來源參照使用位置標記；標題替換已知私密字串。標準設定將提供者涵蓋識別碼及指紋分別替換為 `unit-`、`fp-` 加上原值 SHA-256 的前十二個小寫十六進位字元；產品產生的識別碼、時間、列舉值、分數及摘要維持原值。標準設定下，已確認問題使用在地化的原始碼問題類別摘要、影響與行動；`none` 則完整保留原生文字與程式碼。入案交易完成後自動保存終態快照；若快照保存失敗，入案仍成功，回應提供原入案要求的重播命令。

已簽署案件包會在案件含有入案稽核時加入案件層級的 `source-audit-admissions.json`，即使所選報告僅屬掃描工具輪次亦同。文件保留投影、原件綁定與提供者工作來源。Standard 隱藏提供者文字與程式碼並保留隱藏數量，以位置標記及 `unit-`／`fp-` 假名取代私人識別資訊，同時保留身分與摘要；`none` 保留原生值。入案與原生摘要承諾的是原始資料，簽署清單另行雜湊實際匯出文件。案件包框架報告的 `source_audits` 與其共用報告完全相同，包含隱藏數量。提供者工作不列為目錄引擎版本或產品內建檢查。沒有入案稽核的案件包不新增空文件或 schema 項目。

單輪與整合 HTML 的 ZIP 附件保留原件的精確位元組與巢狀路徑。稽核 ZIP 清單記錄提供者、入案身分、「Cloudflare source audit」方法、原件摘要及逐檔雜湊，ZIP 本身亦有雜湊；整合附件以輪次與工作區隔名稱。只有選擇 `none` 並明確要求原始檔案時才包含提供者原件。Standard 即使選取原始檔案，仍會排除全部提供者原件並計入敏感省略數，不讀取原件，也不製作遮罩衍生副本。原件遺失、變更或綁定不符時，未遮罩的附件與案件包匯出會拒絕。匯出預覽將原始碼稽核工作與掃描引擎工作分開計數。

附件仍受 64 MiB／10,000 個檔案限制；整合報告會合計所有所選輪次，並限制編碼後 HTML／JSON 大小。超限時，含入案稽核與僅有掃描工具的案件皆使用明確同意的私密完整封存保存原件。完整封存可建立、驗證及還原為唯讀歷史；涉及稽核的執行比較仍不可用。詳見[報告快照](report-snapshots.md#admitted-source-audits)。

框架報告現已加入經所選設定遮蔽的共用 `source_audits` 區塊，保留身分、方法、結果、計數、待驗證、缺口及技術來源。稽核工作不計入掃描工具數量或引擎狀態清單。已確認稽核觀察使用 `source_audit_not_mapped`，表示原始碼稽核問題不對照框架控制項。

OCSF 將已確認問題匯出為 Detection Finding 事件；OSCAL 使用 `EXAMINE` 觀察。OCSF 在 `unmapped.ai_security_scanner.source_audit`，OSCAL 在觀察及證據的命名空間屬性 `source-audit-*`，保留提供者與入案識別、原生指紋、紀錄摘要與索引、入案確認判定、方法名稱及上游版本。提供者身分與判定不是人工確認、合規結果或控制項結論；人工處理狀態不變。待驗證、已拒絕及候選紀錄不成為事件或觀察。必要的 OCSF／OSCAL 配套檔以主檔雜湊綁定共用報告，即使沒有已確認問題，也保留線索、缺口、方法與結果；分享時須保留兩檔。

兩種設定均保留識別碼、列舉值與摘要。標準設定沿用共用遮蔽，未解決指紋清單使用相同的 `fp-` 假名；衍生缺口標籤與識別遮蔽不增加文字隱藏數，計數只包含實際隱藏的提供者文字或程式碼。`none` 保留原生值。入案、工作或原件繫結缺失或不符時，在寫出任何檔案前拒絕。


### 未開始或未完成的原始碼稽核

準備受阻會新增一列未執行的 **Cloudflare 原始碼稽核**：「Cloudflare 原始碼稽核未開始。」
明示終止會新增失敗列：「Cloudflare 原始碼稽核未完成即結束。」每列有一項型別化原因及下一步；
例如「稽核流程中斷。」及「開始新的原始碼稽核。」

每列僅有一項所屬資產的涵蓋缺口：受阻為「此資產未執行原始碼稽核。」；終止為
「原始碼稽核未完成即結束，此資產沒有可用的稽核結果。」不新增已測試面向、完成涵蓋、發現或待驗證線索。
技術明細保存原因碼、保管時間與摘要、輪次／工作識別及終止時的派工和擷取計數，套用標準遮蔽。
整合報告保留各輪次與資產身分。

框架報告計為未完成檢查，不產生控制項結論或發現。OCSF／OSCAL 不新增觀察；必要的涵蓋配套保留共用報告列。
案件包保留輪次與工作，匯出預覽不將其計為掃描引擎工作。掃描恢復、重掃、清理、修正檢查與比較不適用。
桌面「掃描結果」顯示相同的結果、原因、下一步及資產缺口，「原始碼稽核」技術明細以結果為首列。兩種結果均可選入整合報告，不提供掃描恢復或確認修復控制。
