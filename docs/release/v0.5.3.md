# v0.5.3 — October 21 incident scan pack

The incident scan pack uses the same desktop app on macOS Universal (Apple Silicon and Intel), Windows x86_64 and Linux x86_64. Its [download entry](https://ted-h-com.github.io/ai-security-scanner/incident-october-21.html) lists only installers actually published in [v0.5.3](https://github.com/TED-H-com/ai-security-scanner/releases/tag/v0.5.3).

Choose **Scan my environment** or **Check code or an AI project**, add the assets you manage, and review the scope. Leave the standard scan selected for its applicable code, secret, dependency, configuration and network checks. Select **October 21–22 incident triage** to narrow the plan to upstream Trivy package checks on supported local repository, IaC and OCI-image copies. Website and internal-host assets use the standard scan.

Both modes use one report model and the same HTML template. Save the HTML report when the scan finishes, or export JSON. The report starts with affected assets, important problems, impact, next actions, verification and coverage. Original scanner identifiers, severity, evidence and remediation remain available in detail.

ISO/IEC 27001:2022, NIST CSF 2.0, AIDEFEND, OWASP and CIS references follow the actionable report. Existing evidence-bound mapping rules determine which references apply; unknown and unmapped relationships remain visible. These relationships do not establish certification or compliance.

The attached `incident-scan-pack.json` contains the reviewed campaign, its SHA-256, exact source commit, platform identities and shared report contract. Incident matches link original upstream findings. A completed general check without a specific finding does not exclude an incident. Account investigations and advisories awaiting public mappings remain separate coverage outcomes. See the [incident coverage record](https://github.com/TED-H-com/ai-security-scanner/blob/main/docs/engines/incident-triage.md) for sources and supported inputs.

Supported external scanner reports can be imported and combined with saved terminal results into one HTML or JSON report while preserving each source and its coverage.

Install using the [installation guide](https://github.com/TED-H-com/ai-security-scanner/blob/main/docs/getting-started.md#install). Exact installer availability, signing and observed runtime checks are recorded in the published release metadata. Publication is complete only when the release and its assets are publicly available.

## Verified engine inputs

The release pins published Trivy `0.76.1-1` with the October 22 offline databases and Nuclei `3.11.1-8` with template revision `f938a3dd530c283e9387b518b97911152ff5846c`. Both amd64 and arm64 image identities, source-bound provenance and per-platform SBOM signatures were verified. The published amd64 Trivy image distinguishes vulnerable and vendor-fixed PHP packages for both October 21 PHP advisories, with networking disabled and the product resource limits. The published Nuclei image detects the expected Nginx exposure in an isolated local fixture. Exact digests, raw-output hashes and execution limits are in [the evidence record](../engines/updates/2026-10-23-publication.json). Local native arm64 execution is not claimed.

Development tooling updates Vite from 8.3.0 to [8.3.3](https://github.com/vitejs/vite/releases/tag/v8.3.3), including the upstream launch-editor fixes for GHSA-587h-7wmj-h5pm, GHSA-698v-4r3x-3vcv and GHSA-r825-w8mm-5pxw.

10/21 事件掃描包在 Mac、Windows、Linux 使用同一個桌面程式。選擇「掃描公司環境」或「檢查程式碼或 AI 專案」，加入資產後確認範圍。一般掃描保留原有安全檢查；勾選「10/21–10/22 事件專項檢查」時，只執行適用本機副本的 Trivy 套件檢查。網站與內部主機使用一般掃描。

掃描包清單將事件資料、SHA-256、報告規格與來源提交綁在同一個 release。未測試、需要調查與公告對應待確認會分別呈現。下載頁只顯示實際發布的安裝檔。
