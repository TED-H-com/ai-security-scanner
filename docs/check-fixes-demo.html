Fix it, then check again.修正して、もう一度確認。修好之後，再檢查一次。

We scanned a small demo project, fixed some of its problems and checked it again. The app compared the two scans.小さなデモプロジェクトをスキャンし、一部の問題を修正して再スキャンしました。アプリで 2 回の結果を比較しています。我們掃描一個小型示範專案，修正其中幾個問題後再檢查一次，由程式比較兩次掃描的結果。

  • 13 → 8Problems found見つかった問題發現的問題
  • 6No longer observed今回は検出されず這次沒有再看到
  • 7Still present引き続き検出仍然存在
  • 1New新規新出現
  • 0Verification incomplete検証未完了驗證未完成

These improvements are included in v0.5.0. This example was made with development builds after v0.4.1: the scans with commit bca90a8, the comparison screenshot with dff42c2, and the reports and other screenshots with e663b0a. v0.4.1 does not have step 4, choosing the fixed folder again (it scans the copy saved when the folder was first chosen), the comparison at the top of the Scan 2 report, or problems that combine related findings: it lists every finding on its own.これらの改善は v0.5.0 に含まれます。この例は v0.4.1 以降の開発ビルドで作成しました。スキャンに使ったコミットは bca90a8、比較画面は dff42c2、レポートとその他の画面は e663b0aです。v0.4.1 には手順 4 のフォルダー再選択、2 回目のレポート冒頭の比較、関連結果をまとめた問題表示がありません。最初に選んだ時点のコピーをスキャンし、各検出結果を個別に表示します。這些改進已納入 v0.5.0。本範例使用 v0.4.1 之後的開發版本製作：掃描使用 commit bca90a8，比較結果截圖使用 dff42c2，報告與其他截圖使用 e663b0a。v0.4.1 沒有第 4 步「重新選擇修正後的資料夾」（它掃描的是第一次選擇資料夾時保存的副本），沒有第 2 次掃描報告開頭的比較，也不會把相關的發現合併成一個問題，而是逐筆列出。

01

A small API with planted problems意図的に問題を入れた小さな API一個刻意放入問題的小型 API

inventory-api-demo is a small Flask service written for this demo. It has five planted problems:inventory-api-demo は、このデモ用の小さな Flask サービスです。次の 5 つの問題を入れています。inventory-api-demo 是為這次示範寫的小型 Flask 服務，刻意放入五種問題：

  • a private deploy key in the folder, created for this demo and never used anywhere;デモ用に作成し、一度も使用していないデプロイ用の秘密鍵をフォルダーに保存。資料夾裡有一把部署用私鑰，為示範而產生，從未在任何地方使用；
  • YAML input loaded with the unsafe loader;YAML 入力を安全でないローダーで読み込み。用不安全的方式載入 YAML 輸入；
  • PyYAML 5.3.1, which has a known critical vulnerability;既知の緊急の脆弱性がある PyYAML 5.3.1 を使用。使用有已知重大弱點的 PyYAML 5.3.1；
  • a container that runs as root;コンテナーを root で実行。容器以 root 身分執行；
  • a ping endpoint that passes user input to a shell.ping のエンドポイントで、ユーザー入力をシェルに渡す。ping 端點把使用者輸入交給 shell 執行。

02

First scan: 13 problems1 回目：13 件の問題第一次掃描：13 個問題

The app scanned the folder with eight tools in about 13 minutes on the test computer. All eight completed. The report shows their 26 findings as 13 problems, 6 of them Critical or High, and starts with the vulnerable PyYAML version.テスト用コンピューターで、8 ツールが約 13 分で完了しました。26 件の検出結果を 13 件の問題にまとめ、うち 6 件が緊急または高です。レポートは脆弱な PyYAML の版から表示します。程式用八個工具掃描這個資料夾，在測試電腦上約 13 分鐘完成，八個工具都跑完。報告把它們的 26 筆發現整理成 13 個問題，其中 6 個是重大或高風險，並建議先處理有弱點的 PyYAML 版本。

04

Choose the fixed folder again修正後のフォルダーを再選択重新選擇修正後的資料夾

A scan reads a copy of the folder saved when you choose it. Before checking again, choose the folder again in My scans → Check fixes. Here the new copy had 3 files changed, 1 added and 1 removed.スキャンはフォルダー選択時に保存したコピーを読みます。「マイスキャン → 修正を確認」でフォルダーを選び直してください。この例の新しいコピーは、変更 3 ファイル、追加 1、削除 1 でした。掃描讀取的是選擇資料夾時保存的副本。再次檢查前，先到「我的掃描 → 確認修復」重新選擇資料夾。這次的新副本有 3 個檔案變更、1 個新增、1 個移除。

06

What this demo does not showこのデモの対象外這次沒有涵蓋的部分

  • The deleted key is still in the project's git history and in any earlier copy. The folder scan no longer finds it, but a real key must still be revoked or rotated.削除したキーは Git 履歴や以前のコピーには残っています。フォルダー検査で検出されなくても、本物のキーなら無効化や更新が必要です。刪除的私鑰仍留在專案的 git 歷史與先前的副本中。資料夾掃描已找不到它，但真實的金鑰仍要撤銷或更換。
  • Only the source folder was checked. The service was not run, no container image was built and no website was tested.調べたのはソースフォルダーのみです。サービスの起動、コンテナーイメージの作成、ウェブサイトの検査は行っていません。這次只檢查原始碼資料夾：沒有執行服務、沒有建置容器映像，也沒有測試網站。
  • 7 problems remain, and the new debug setting must be turned off before deployment.7 件の問題が残り、新しいデバッグ設定もデプロイ前に無効化する必要があります。仍有 7 個問題，新開啟的除錯設定也必須在部署前關閉。
