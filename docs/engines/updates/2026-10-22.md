## Repeating proposal generation

After fetching and reviewing source checkout changes, regenerate the research lock with `node scripts/lock-upstreams.mjs`. Run `npm run upstream:refresh -- --engine <id>` for each selected existing policy entry, then inspect the emitted `proposal.json`, `changes.patch` and `report.md`. `npm run upstream:propose -- --bundle <path> --no-open-pr` records the local decision and prints review commands without executing them.

This existing workflow is deterministic and offline. Its `no_change` result means the available local inputs match the plan; it does not mean an internet release check found no newer version. Revision-only proposals remain ineligible until source archive checksums, Dockerfile pins, dependency/rule closure and real replacement image validation agree. Frozen engines remain refused. It is not an automatic runtime promotion or a scheduled refresh service.
